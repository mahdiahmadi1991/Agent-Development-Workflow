# Contributing

## Branch Workflow
1. Create or update work on `develop`.
2. Open a pull request from `develop` to `main`.
3. Merge only after explicit project approval.

## Contribution Principles
- Keep artifacts generic and reusable.
- Avoid business/domain-specific assumptions.
- Document rationale for architecture changes.
- Prefer small, reviewable pull requests.

## Commit Guidance
- Use clear, descriptive commit messages.
- Keep commits scoped to one concern when possible.
