# Contributing

## Branch Workflow
1. Create or update work on `develop`.
2. Open a pull request from `develop` to `main`.
3. Merge only after explicit project approval.
4. For maintainer-driven sessions, do not commit/push until explicit user approval is provided.

## Contribution Principles
- Keep artifacts generic, reusable, and domain-agnostic.
- Keep the scope Codex-only.
- Keep governance and onboarding artifacts English-only.
- Avoid business/domain-specific assumptions.
- Document rationale for architecture changes.
- Prefer small, reviewable pull requests.
- Do not edit managed core onboarding files directly when testing consumer flows; use override paths.

## Commit Guidance
- Use clear, descriptive commit messages.
- Keep commits scoped to one concern when possible.
